# Writing style

## Voice

- Write like a developer helping another developer.
- Use plain, friendly English.
- Be direct.
- Explain why each important step works.
- Do not use marketing language, jokes, or filler.

## Structure

1. Start with the problem and the result.
2. Give only the context the reader needs.
3. Put the steps in the order the reader will do them.
4. Use clear, title-case headings.
5. Introduce each code block before showing it.
6. Explain the important lines after the code.
7. End with a short summary.

## Text and code

- Keep paragraphs short. One to three sentences is normal.
- Use common words.
- Define a technical term the first time it appears.
- Use real examples.
- Wrap commands, files, and code names in backticks.
- Use the right language on fenced code blocks.
- Keep examples complete and consistent.
- Use numbered lists for steps. Use bullets for options or checks.

## Metadata

- Use a clear, search-friendly title.
- Write a one-sentence description of about 15–30 words.
- Use a short, lowercase, hyphenated slug.
- Keep an existing slug unless the user asks to change it.
- Reuse the database's current tag names.

## Final check

- The opening states the problem and result.
- The steps can be followed in order.
- The code and names are consistent.
- The conclusion is short.
- The title, description, slug, date, tags, and links are correct.
